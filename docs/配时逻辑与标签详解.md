# 配时逻辑与标签详解

> 本文讲清楚三件事：① 红绿灯的**配时逻辑**——周期怎么算、偏移时间（相位错开）怎么算、红灯时长怎么算；② 每个**标签**的含义；③ **lockerName / groupName** 是什么、怎么绑定。
> 不需要记任何具体路口的数据，按这里的通用方法就能算出你自己路口的配时。

---

## 一、标签大全

每个灯实体上有以下标签（Labels）：

| 标签名 | 类型 | 谁来填 | 作用 |
|--------|------|--------|------|
| `绿灯时长` | number | 你 | 绿灯持续秒数（按你的交通方案需求定） |
| `黄闪时长` | number | 你 | 黄灯持续秒数 |
| `红灯时长` | number | **公式算出** | 红灯持续秒数（见第三节） |
| `全红时长` | number | 你（五态用） | 黄灯后的全红清空时间；三态路口填 0 |
| `偏移时间` | number | **公式算出** | 该灯绿灯起点相对周期起点的偏移（相位错开） |
| `phase` | string | 脚本自动维护 | 当前状态：GREEN / YELLOW / ALLRED / RED / YELLOW2 |
| `lockerName` | pointer | 你（拖入） | 指向该灯方向的 Locker |
| `groupName` | pointer | 你（拖入） | 指向该灯方向 ControlArea 所在的 Group |

## 二、lockerName / groupName 详解 ⭐

**为什么需要这两个标签？**

灯的占用逻辑要回答一个问题："我（这个灯）负责锁/放哪些 ControlArea？" 答案存在这两个**指针标签**里：

| 标签 | 指向 | 含义 |
|------|------|------|
| `lockerName` | Locker 对象（AGV Resource） | 本灯用哪个 Locker 去加锁/解锁 |
| `groupName` | Group 对象（Toolbox） | 本灯方向的 ControlArea 都归在哪个 Group |

**绑定方法**：

1. 标签类型必须选 **Pointer**（不是 string，也不是 number）；
2. 从模型树把对应的 Locker 拖到 `lockerName` 的值区；
3. 从模型树把对应的 Group 拖到 `groupName` 的值区；
4. 绑定成功后标签值显示对象名 + 箭头图标。

**对照关系**（一个方向一套，灯指向自己方向的那套）：

| 灯 | lockerName | groupName |
|----|------------|-----------|
| 南北方向的灯 | `TrafficLightLocker_NS` | `NS_Stop_CA_Group` |
| 东西方向的灯 | `TrafficLightLocker_EW` | `EW_Stop_CA_Group` |

**为什么用标签而不是写死在代码里？** 因为这样"一个灯"就是通用模块：复制到任何方向/路口，只改这两个标签（+ 配时标签），代码一行不用动。这就是"复制即用、只改标签"的模块化思路。

**代码里怎么用**：灯的 OnMessage 里 `getlabel(light, "lockerName")` / `getlabel(light, "groupName")` 取出对象 → 遍历 groupName 指向的 Group 成员（都是 ControlArea）→ 用 lockerName 指向的 Locker 执行锁定/释放。完整逻辑见 [控制区域与占用逻辑详解](控制区域与占用逻辑详解.md)。

## 三、配时逻辑：周期、红灯时长、偏移时间

### 3.1 先定状态机（周期公式）

- **三态**（两相位路口）：`GREEN → YELLOW → RED → GREEN`

  ```
  周期 = 绿灯时长 + 黄闪时长 + 红灯时长
  红灯时长 = 周期 - 绿灯时长 - 黄闪时长
  ```

- **五态**（有全红清空的路口）：`GREEN → YELLOW → ALLRED → RED → YELLOW2 → GREEN`

  ```
  周期 = 绿灯时长 + 黄闪时长 + 全红时长 + 红灯时长 + 黄闪时长
  红灯时长 = 周期 - 绿灯时长 - 黄闪时长 - 全红时长 - 黄闪时长
  ```

先定好每个相位的绿灯/黄闪/全红需求（这是交通方案的事），周期和红灯时长就跟着定了。

### 3.2 偏移时间 = 相位错开（核心公式）⭐

**同一路口所有灯的周期必须相等。** 各灯用"偏移时间"把绿灯起点错开，保证任意时刻只有一个方向组是 GREEN：

```
灯 N 的偏移时间 = 前面所有灯（绿灯 + 黄闪 [+ 全红]）之和
```

- 三态：累加的是 `绿灯 + 黄闪`；
- 五态：累加的是 `绿灯 + 黄闪 + 全红`（⚠️ 不是只加绿灯+黄闪）。

**通用示例**（两相位、三态）：

```
灯 1：绿灯 23s，黄闪 3s，红灯 68s   → 偏移 0
灯 2：绿灯 20s，黄闪 3s，红灯 71s   → 偏移 = 23 + 3 = 26

时间轴：
0        23  26                    94
├─ 灯1 GREEN ─┤Y├──── 灯1 RED ──────┤
│    26        46  49              94
├─ 灯2 RED ────┤├─ 灯2 GREEN ─┤Y├──┤
```

灯 1 绿灯在 0~23，灯 2 绿灯在 26~46，互不重叠 → 任意时刻只有一个方向放行。

**为什么模型一启动就能对上相位？** OnModelStart 里用 `fmod(偏移时间, 周期)` 算出"当前时刻落在状态机的哪个位置"，模型一启动所有灯就处于正确的相位，不需要等第一个完整周期。

### 3.3 校验（设置完后自查）

1. **同路口所有灯周期相等**：`周期 = 绿灯+黄闪(+全红+黄闪)+红灯` 对每个灯都成立；
2. **偏移 = 前面各灯之和**：灯 N 偏移 = 灯 1 ~ 灯 (N-1) 的（绿灯+黄闪+全红）累加；
3. **绿灯窗口不重叠**：任意时刻只有 1 个灯为 GREEN；
4. **首尾相接**：最后一个灯的黄闪2 结束时间对齐下一周期第一个灯的绿灯起点。

## 四、通用设置流程

1. 创建灯实体（数量 = 该路口相位方向数），从库拖入或复制已有灯；
2. 填配时标签：`绿灯时长`、`黄闪时长`、`全红时长`（五态）、`红灯时长`（公式算）、`偏移时间`（公式算）；
3. 绑定 `lockerName` / `groupName`（Pointer，拖入 Locker 和 Group）；
4. 初始化脚本预锁所有方向 ControlArea；
5. 运行，验证"同一时刻只有一个方向 GREEN"。

> 本仓库附带的模型 `models/红绿灯.fsm` 里各灯的标签值，就是按这套公式算好的一组实际例子，可以直接打开对照学习。
