# 红绿灯模型：3D 外观构建与工作原理

> 本文说明红绿灯模型的 **3D 外观**是怎么搭出来的（灯柱 + 三个灯、外部 FBX 模型、用户库打包），以及**工作原理**的核心——控制区域（ControlArea）的放置位置与占用/放行逻辑。
> 逻辑脚本与配时数值见 [部署指南](../README.md)；配时计算方法见 [配时逻辑与标签详解](配时逻辑与标签详解.md)。

---

## 一、模型整体结构

一个"灯"实体由两层组成：

| 层次 | 内容 | 作用 |
|------|------|------|
| **逻辑层** | 1 个 TaskExecuter + 3 个 DrawSurrogate（`red`/`green`/`yellow` 子实体） | 状态机轮转、颜色切换、占用/放行控制 |
| **外观层** | 1 个灯柱模型 + 3 个灯模型（外部 FBX，作为子模型挂接） | 3D 视觉效果，可自由替换 |

**外观与逻辑分离**：换外观不影响逻辑，换逻辑不影响外观。

## 二、外部模型（FBX）用法

FlexSim 支持把外部 3D 模型文件（FBX 等）挂到实体上。**模型文件本身不保存 3D 内容，只保存文件路径引用**——这就是"路径要求"的由来。

本模型用到的 FBX 文件（已随仓库附在 `models/fbx/`）：

| 文件 | 角色 |
|------|------|
| `杆横向.fbx` | 灯柱（横臂，内部对象名 `Arm_Horizontal`），挂在灯实体上 |
| `灯0.fbx` | 灯体模型，**三个灯（红/黄/绿）复用同一个灯体**，在 FlexSim 中分别着色区分 |

> ⚠️ **路径注意事项**：模型保存的是构建时的绝对路径（如 `C:\Users\...\FlexSimChinese 2026 Projects\杆横向.fbx`）。在别的电脑打开时会找不到文件、显示不出 3D 外观。修复方式：
> 1. 把仓库 `models/fbx/` 下的两个 FBX 复制到本机任意目录；
> 2. 在 FlexSim 中打开模型，重新指定外观路径（选中灯实体 → 外观/形状属性 → 重新选择 FBX），或在模型属性中把引用改为相对路径/加入搜索路径。

## 三、组装步骤（灯柱 + 三个灯子模型）

在 FlexSim 中把灯柱和三个灯组装成一个整体：

1. **导入灯柱模型**：把 `杆横向.fbx` 挂到灯实体上（实体外观选择外部模型）；
2. **选中灯柱**，进入 **编辑 → 动画**（Edit → Animation）窗口；
3. 在动画窗口中 **添加子模型（Add Sub-Model）**；
4. 子模型选择灯体模型 `灯0.fbx`，**添加 3 次**（红、黄、绿三个灯）；
5. 分别调整三个子模型的位置（对准灯柱上的灯位）与颜色（红/黄/绿），并把 DrawSurrogate 的 `red`/`green`/`yellow` 对齐到对应灯位。

> 三个灯复用同一个灯体模型（`灯0.fbx`），通过 FlexSim 的着色区分颜色；想换成别的灯型，替换子模型的 FBX 即可。

## 四、打包为用户库（.fsl）

把做好的红绿灯实体保存为用户库，之后任何模型都能直接从库面板拖出来用：

1. 在 FlexSim 的 **库面板** 中新建用户库，把做好的红绿灯实体拖入；
2. 保存为用户库文件（.fsl），例如 `trafficlight.fsl`；
3. **安装到 FlexSim**（二选一）：
   - 把 `.fsl` 放到 FlexSim 的库目录下，例如 `D:\Common\flexsim\libraries\TerminalSim\trafficlight.fsl`；
   - 或：FlexSim 菜单 **工具 → 全局设置 → 用户库 → 添加**，选择 `.fsl` 文件路径；
4. 之后在库面板搜索 "trafficlight"，即可直接拖出红绿灯实体。

> 本仓库附带 `models/trafficlight.fsl`（红绿灯用户库文件），按上面第 3 步注册即可使用。

## 五、工作原理

### 1. 信号状态机

每个灯用 `phase` 标签记录当前状态，靠 `senddelayedmessage` 定时推进（详见 [部署指南](../README.md) 的模型原理）：

- 基本状态循环：`GREEN → YELLOW → RED → GREEN`，用 `phase` 标签记录、`senddelayedmessage` 定时切换

### 2. 控制区域（ControlArea）的放置位置 ⭐

**ControlArea 是 AGV 的"停车线"**，铺在 AGV 路径上，灯变红时 AGV 在 ControlArea 内停车等待。

放置规则：

| 方向组 | ControlArea 位置 | 归入 Group |
|--------|------------------|------------|
| 南北（NS） | 南北方向进口道、**路口冲突区之前**的路径段（停车线位置） | `NS_Stop_CA_Group` |
| 东西（EW） | 东西方向进口道、**路口冲突区之前**的路径段（停车线位置） | `EW_Stop_CA_Group` |
| 右转（不受控） | **不放** ControlArea，右转始终自由 | — |

要点：

- ControlArea 放在**冲突区之外**（停车线处），保证停在里面的 AGV 不会堵住交叉口；
- 每个方向可放多个 ControlArea（路径较长时分段），全部归入该方向的 Group；
- 一个 ControlArea 只归入一个 Group，避免方向间互锁冲突；
- 右转不受控方向不放 ControlArea（右转在多个相位都有窗口）。

### 3. 占用/放行逻辑 ⭐

三级配合：**Locker → Group → ControlArea**

| 组件 | 作用 |
|------|------|
| `Locker` | 对一组 ControlArea 统一加锁/解锁（一个方向一个 Locker） |
| `Group` | 把该方向所有 ControlArea 归为一组 |
| `ControlArea` | 停车/禁行区本体 |

规则：**绿灯 = 解锁（放行），红灯 = 锁定（停车）**。

实现上有两条等价路径：

- **OnMessage 直控（可加双保险）**：灯实体 OnMessage 里读取 `lockerName`/`groupName` 标签，离开 GREEN 时锁定该方向全部 ControlArea，进入 GREEN 时释放；可另加 ProcessFlow 子流程做同样的事作为双保险。
- **ProcessFlow 轮询**：ProcessFlow 子流程死循环轮询灯的 `phase` 标签——为 GREEN 时 `deallocate` 放行，变红后重新 `allocate` 锁定。

**初始化顺序**：模型启动时先由初始化脚本把**所有方向锁定**（防止初始误放行），随后各灯按 `偏移时间` 进入自己的相位，绿灯方向依次被释放。

### 4. 一个关键细节：为什么不会撞车

- 同一路口所有灯**周期相同**、`偏移时间` 错开绿灯窗口 → 任意时刻只有一个方向组为 GREEN（见 [配时逻辑与标签详解](配时逻辑与标签详解.md) 的偏移校验）；
- 红灯方向 ControlArea 保持锁定 → AGV 停在停车线外；
- 绿灯方向释放 → AGV 通过冲突区；

## 六、别人拿到后可以怎么改

| 想改什么 | 改哪里 |
|----------|--------|
| 灯的外观 | 替换 `models/fbx/` 里的 FBX，或重做子模型（编辑 → 动画） |
| 红绿灯样式 | 修改 `trafficlight.fsl` 用户库，重新拖入 |
| 配时/周期 | 改灯实体的标签值（绿灯时长/黄闪时长/红灯时长/偏移时间） |
| 控制区域位置 | 移动/增删 ControlArea，调整 Group 成员 |
| 放行顺序 | 改偏移时间，或调整 ProcessFlow 子流程的监听灯 |
| 逻辑本身 | 改 Global Code 函数与灯触发器脚本（见 [部署指南](../README.md)） |
