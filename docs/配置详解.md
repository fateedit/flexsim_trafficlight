# 配置详解：先干嘛后干嘛

> 从零到跑通一个路口红绿灯的**完整配置顺序**。本文只讲"按什么顺序配置什么、每步在哪做、注意什么"，代码和原理见对应文档。
> 一句话顺序原则：**先准备"被控对象"（控制区 → 组 → 锁），再造"控制者"（灯），再上"调度"（初始化 + ProcessFlow），最后验证。**

---

## 一、总顺序速查表（先干嘛后干嘛）

| 顺序 | 做什么 | 在哪做 | 产出 |
|:---:|--------|--------|------|
| 0 | 搭 AGV 路网 | 模型视图 | 路径 + AGV + 任务 |
| 1 | **放 ControlArea（控制点）** | AGV 路网上 | 每个方向的停车控制区 |
| 2 | 建 Group 并分组 | Toolbox | 方向组 |
| 3 | 建 Locker | 库 → AGV → Resource | 方向锁 |
| 4 | 建灯实体 + 子实体/外观 | 库 → Task Executers | 灯 |
| 5 | 填标签 + 绑定 lockerName/groupName | 灯属性 → Labels | 配置数据 |
| 6 | 贴脚本（Global Code + 触发器） | Scripts / Triggers | 逻辑 |
| 7 | 初始化预锁 | Model 触发器 | 启动安全 |
| 8 | ProcessFlow 放行子流程 | ProcessFlow | 放行控制 |
| 9 | 联调验证 | 运行 | 跑通 |

- 第 1~3 步和第 4 步可以并行，但**第 5 步（绑定标签）必须等第 2、3 步完成**；
- 第 6 步引用第 5 步的标签，第 7 步引用第 2、3 步的 Group/Locker，顺序不能反。

## 二、第 0 步：AGV 路网（前提）

- 模型里先有 **AGV 路网**：NetworkNode + 路径 + AGV（+ 搬运任务）；
- 红绿灯只控制"经过路口的 AGV"，没有路网就无从谈起；
- 验证：AGV 能沿路网跑通。

## 三、第 1 步：ControlArea（控制点）⭐

ControlArea 是 AGV 路网中的**控制点（控制区域）**，也是整个系统唯一真正"拦车"的东西。

1. **添加**：选中路网节点右键 → Add ControlArea（或从 AGV 面板添加；不同 FlexSim 版本入口略有差异）；
2. **位置**：放在该方向进口道的**停车线处**——即进入路口冲突区**之前**的路径段（示意图见 [控制区域与占用逻辑详解](控制区域与占用逻辑详解.md)）；
3. **覆盖范围**：调整矩形大小，覆盖该方向的车道宽度；
4. **数量**：一个方向一个或多个（路径长可分多个），右转不受控方向**不放**；
5. **验证**：运行后 AGV 到达控制区时会停车（此时还没建灯，先确认控制区本身生效）。

> 灯的锁/放，锁的就是这些 ControlArea。位置放错（放进冲突区里）会让停在里面的车堵住路口。

## 四、第 2 步：Group（分组）

- 在 **Toolbox** 新建 Group，命名如 `NS_Stop_CA_Group`、`EW_Stop_CA_Group`；
- 把**该方向**的所有 ControlArea 拖入对应的 Group；
- 一个 ControlArea 只进一个组；
- 命名随意，但**必须与后面脚本、标签、初始化脚本里用的名字完全一致**（大小写敏感）。

## 五、第 3 步：Locker（锁）

- 从 **库 → AGV → Resource** 拖入，命名如 `TrafficLightLocker_NS`、`TrafficLightLocker_EW`；
- 一个方向一个，不用改属性——它只是"占用者身份"；
- 命名同样要与后续引用一致。

## 六、第 4 步：灯实体

- 从 **库 → Task Executers → TaskExecuter** 拖入，按方向命名（如 `TrafficLight_1_NS_N2S`）；
- 每个灯 = 1 个实体 + 3 个子实体（`red` / `green` / `yellow`，DrawSurrogate 或 3D 外观子模型）；
- 3D 外观（FBX、用户库）可以后加，不影响逻辑（见 [模型3D外观与用户库](模型3D外观与用户库.md)）。

## 七、第 5 步：标签 + 绑定（配置数据）

- 在灯属性 → Labels 添加标签（见 [配时逻辑与标签详解](配时逻辑与标签详解.md)）：

  | 标签 | 类型 | 怎么填 |
  |------|------|--------|
  | `绿灯时长` / `黄闪时长` / `全红时长` | number | 按交通方案 |
  | `红灯时长` / `偏移时间` | number | 按公式算 |
  | `phase` | string | 脚本维护，初始 GREEN |
  | `lockerName` | **pointer** | 拖入该方向 Locker |
  | `groupName` | **pointer** | 拖入该方向 Group |

- 每个灯都要绑定自己的方向和 lockerName/groupName；
- 配时数值用公式算，别拍脑袋（见 [配时逻辑与标签详解](配时逻辑与标签详解.md)）。

## 八、第 6 步：脚本（逻辑）

1. **Global Code**：粘贴通用变色函数 `setLightColor`（三个路口共用一份）；
2. **每个灯**三个触发器：`OnReset`（灰色复位）、`OnModelStart`（偏移对时 + 启动循环）、`OnMessage`（状态转移 + 变色 + 锁定/释放）；
3. ⚠️ **`senddelayedmessage` 必须放在占用逻辑之前**（否则占用逻辑抛异常会打断消息循环）。

代码见 [部署指南](../README.md)。

## 九、第 7 步：初始化预锁（启动安全）

- 在 **Model 触发器**（OnModelStart 或独立触发器）里，把所有方向的 ControlArea **预先锁定**；
- **不做这步**：模型启动瞬间 AGV 会闯进路口；
- 脚本里 `Model.find` 的 Locker/Group 名称必须与第 2、3 步**一字不差**，否则会静默跳过、无报错。

## 十、第 8 步：ProcessFlow（放行调度）

- 每个方向组建一个子流程，轮询灯的 `phase` 标签：GREEN → 释放（deallocate），变红 → 重新锁定（allocate）；
- 模板见 [部署指南](../README.md) 第九步；
- 1号路口可在灯 OnMessage 直控 + ProcessFlow 双保险；2/3号路口由 ProcessFlow 负责。

## 十一、第 9 步：联调验证

- [ ] 灯颜色按预期轮转（三态/五态）
- [ ] 同一时刻只有 1 个方向组为 GREEN
- [ ] 绿灯方向 AGV 通行
- [ ] 红灯方向 AGV 在 ControlArea 前停车
- [ ] 控制台有放行/锁定日志，且不重复
- [ ] 复位（Reset）后一切归位

## 十二、常见顺序错误

| 错误 | 后果 | 正确做法 |
|------|------|----------|
| 先建灯、后放 ControlArea | 灯没有可锁/放的对象，占用逻辑空转 | 先放控制区、分好组 |
| Group/Locker 没建就绑标签 | 拖不进标签，或绑错对象 | 先建 Group/Locker 再绑定 |
| 命名不一致（Group/Locker/灯名） | 初始化脚本找不到对象，**静默跳过**，启动闯灯 | 先定命名规范，全程一致 |
| 忘初始化预锁 | 启动瞬间 AGV 闯进路口 | 第 7 步必做 |
| ControlArea 放进冲突区内 | 停在里面的车堵住路口 | 放停车线处（冲突区之前） |
| 配时数值直接填 | 周期不一致 → 多灯同时 GREEN | 用公式算（见配时逻辑文档） |
