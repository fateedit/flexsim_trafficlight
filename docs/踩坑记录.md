# 红绿灯模块 — 踩坑记录与解决方案

> 记录开发过程中遇到的所有报错、原因分析、修复方法。
> 每个坑按"现象 → 报错 → 根因 → 修复"结构组织，方便日后排查。

---

## 坑 1：灯不变色 / 循环中断

**现象**：模型启动后灯亮了第一次，之后再也不变色。

**控制台可能看到的错误**（不一定出现）：
```
Invalid down cast. Object is not an instance of the target type.
```

**根因**：`senddelayedmessage` 放在了占用逻辑**后面**。

```cpp
// ❌ 错误顺序
// ... 颜色控制 ...
// ... 占用逻辑（锁定/释放）...  ← 这里如果报错，下面这行永远不会执行
senddelayedmessage(light, delay, current);   // 消息循环断了！
```

占用逻辑里一旦抛异常（比如 Invalid down cast），`senddelayedmessage` 就永远到不了，消息循环直接死掉。

**修复**：`senddelayedmessage` 永远放在占用逻辑**之前**。

```cpp
// ✅ 正确顺序
// ... 颜色控制 ...
senddelayedmessage(light, delay, current);   // 先发消息，无论如何循环不会断
// ... 占用逻辑（锁定/释放）...              // 后面即使报错也不影响循环
```

## 坑 2：`Invalid down cast` — 遍历 Group 内部节点

**现象**：
```
FlexScript exception: Invalid down cast. Object is not an instance of the target type.
at MODEL:/trafficlight4>variables/messagetrigger
```

**出错代码**：
```cpp
Object grp = getlabel(light, "groupName");
for (int i = 1; i <= grp.subnodes.length; i++) {
    Object caObj = grp.subnodes[i];          // ← subnodes 包含了非 ControlArea 节点
    AGV.AllocatableObject ca = caObj.as(AGV.AllocatableObject);  // ← 崩在这里
}
```

**根因**：`grp.subnodes` 遍历的是 Group 的**全部内部子节点**，包括 FlexSim 自动生成的系统节点（不是用户手动添加的 ControlArea 成员）。这些节点不是 `AGV.AllocatableObject` 类型，`.as()` 强转就崩。

**修复**：不遍历 `subnodes`，用 `Group()` 构造对象后按**成员索引**遍历。

```cpp
Object grp = getlabel(light, "groupName");
Group theGroup = Group(grp.name);            // 通过名称拿到真正的 Group 对象
for (int i = 1; i <= theGroup.length; i++) {
    Object caObj = theGroup[i];              // 按成员索引，只返回组内成员
    AGV.AllocatableObject ca = caObj.as(AGV.AllocatableObject);  // 安全
}
```

**关键区别**：

| 方式 | 返回内容 | 是否安全 |
|------|----------|----------|
| `grp.subnodes[i]` | Group 全部子节点（含内部节点） | ❌ 会崩 |
| `Group(grp.name)[i]` | Group 成员（只含用户添加的 ControlArea） | ✅ 安全 |

## 坑 3：`deallocate` 命令不存在

**现象**：
```
Unknown command deallocate being called
```

**出错代码**：
```cpp
AGV.AllocatableObject ca = caObj.as(AGV.AllocatableObject);
ca.deallocate(locker);   // ← AllocatableObject 上没有 deallocate 方法
```

**根因**：`deallocate` 是 **`AGV.AllocationPoint`** 上的方法，不是 `AGV.AllocatableObject` 上的。

**修复**：在 `AllocationPoint` 上调用。

```cpp
AGV.AllocatableObject ca = caObj.as(AGV.AllocatableObject);
for (int j = 1; j <= ca.allocations.length; j++) {
    AGV.AllocationPoint ap = ca.allocations[j];   // 取到 AllocationPoint
    if (string(ap.allocator.name) == locker.name) {
        ap.deallocate();                           // ✅ 在 AllocationPoint 上调
    }
}
```

**层级关系**：
```
AllocatableObject (ControlArea 本身)
└── allocations[]   ← 数组，每个元素是 AllocationPoint
    └── allocate()  ← AllocatableObject 上可以加锁
    └── deallocate() ← 但这个在 AllocationPoint 上才能调！
```

## 坑 4：`free` 命令不存在

**现象**：
```
Unknown command free being called
```

**出错代码**：
```cpp
ca.free();   // ← 不存在
```

**根因**：`free` 不是 `AGV.AllocatableObject` 的有效方法。

**修复**：同坑 3，用 `ap.deallocate()`。

---

## 坑 5：`allocations[j] = 0` 赋值报错

**现象**：
```
Invalid type for left side of assignment operation. Must be valid l-value. Type is AGV.AllocationPoint
```

**出错代码**：
```cpp
ca.allocations[j] = 0;   // ← AllocationPoint 不能直接赋值为 0
```

**根因**：`AGV.AllocationPoint` 不是简单类型，不能用 `=` 赋值。

**修复**：用 `ap.deallocate()`。

---

## 坑 6：LOCKED / UNLOCKED 重复执行（防重锁失效）

**现象**：每次状态切换，同一个 ControlArea 被锁定/释放了多次。

**控制台日志**：
```
LOCKED: NS_Stop_CA by TrafficLightLocker_NS
LOCKED: NS_Stop_CA by TrafficLightLocker_NS    ← 同一个 CA 锁了两次！
UNLOCKED: NS_Stop_CA
UNLOCKED: NS_Stop_CA                            ← 同一个 CA 释放了两次！
```

**出错代码**：
```cpp
int alreadyLocked = 0;
for (int j = 1; j <= ca.allocations.length; j++) {
    AGV.AllocationPoint ap = ca.allocations[j];
    if (ap.allocator == locker) { alreadyLocked = 1; break; }  // ← 引用比较
}
```

**根因**：`getlabel(light, "lockerName")` 拿到的 Locker 对象引用，和 `Model.find("...")` 拿到的**不是同一个内存引用**。FlexSim 指针标签存的是引用，但不同获取方式产生的引用不同。`==` 比较的是**内存地址**而非对象标识，所以永远返回 `false`，`alreadyLocked` 永远是 0，防重锁逻辑形同虚设。

**修复**：用**名称字符串比较**替代引用比较。

```cpp
int alreadyLocked = 0;
for (int j = 1; j <= ca.allocations.length; j++) {
    AGV.AllocationPoint ap = ca.allocations[j];
    if (string(ap.allocator.name) == locker.name) { alreadyLocked = 1; break; }  // ✅ 名称比较
}
```

> ⚠️ 注意 `ap.allocator.name` 返回的是 `treenode` 类型，需要用 `string()` 包裹后才能和字符串比较。

**两种比较方式对比**：

| 比较方式 | 写法 | 效果 |
|----------|------|------|
| 引用比较 | `ap.allocator == locker` | ❌ 不同来源拿到的引用不同，永远 false |
| 名称比较 | `string(ap.allocator.name) == locker.name` | ✅ 名称相同即判定为同一对象 |

## 坑 7：释放时跳过元素

**现象**：每隔一个元素才释放一个，有些 ControlArea 没有被释放。

**根因**：`ap.deallocate()` 会从数组中**移除当前元素**，数组长度缩水。如果正序遍历，删除索引 `j` 后，原来的 `j+1` 变成了新的 `j`，但循环会 `j++` 跳到 `j+1`，导致跳过一个元素。

```
正序 j=1,2,3,4... 删除 j=1 → 数组变为 [2,3,4] → j++ = 2 → 但原来的 2 现在是索引 1，被跳过了！
倒序 j=4,3,2,1... 删除 j=4 → 数组变为 [1,2,3] → j-- = 3 → 不受影响 ✅
```

**修复**：**倒序遍历**。

```cpp
// ✅ 倒序
for (int j = ca.allocations.length; j >= 1; j--) {
    AGV.AllocationPoint ap = ca.allocations[j];
    if (string(ap.allocator.name) == locker.name) {
        ap.deallocate();
    }
}
```

## 坑 8：初始化被跳过但无错误提示

**现象**：模型启动后 init 脚本没有执行，ControlArea 没被锁定，启动瞬间 AGV 闯进路口。

**出错代码**：
```cpp
if (!nsLocker) {
    pt("Init: Cannot find TrafficLightLocker_NS\n");
    return 0;
}
```

**根因**：`Model.find("TrafficLightLocker_NS")` 没找到对象（名称不匹配），直接就 `return 0` 退出了，后续 EW 的锁定代码也跳过了。删掉 `pt()` 调试日志后，这个错误更隐蔽。

**修复**：
1. 核对 Locker 名称是否完全一致（大小写敏感）
2. 暂时加回 `pt()` 或 `msg()` 输出调试信息排查
3. 在实际部署时，考虑把初始化放在一个不会被轻易跳过的位置（如 Model 的 OnModelStart）

## 总结速查表

| 坑 | 错误信息 | 一句话原因 | 一句话修复 |
|----|----------|-----------|-----------|
| 1 灯不变色 | 无报错但灯不循环 | `senddelayedmessage` 放错位置 | 移到占用逻辑之前 |
| 2 down cast | Invalid down cast | `subnodes` 遍历了非 CA 节点 | 用 `Group(name)[i]` 成员索引 |
| 3 deallocate | Unknown command deallocate | 调错了对象层级 | 在 `AllocationPoint` 上调 `ap.deallocate()` |
| 4 free | Unknown command free | 不存在这个方法 | 同上 |
| 5 赋值 | Invalid type for left side | 不能直接赋值 AllocationPoint | 用 `ap.deallocate()` |
| 6 重复锁 | LOCKED 打印多次 | `==` 引用比较失败 | 用 `string(ap.allocator.name) == locker.name` |
| 7 跳过释放 | 部分 CA 没释放 | 正序遍历 + 删除导致跳元素 | 倒序 `j--` |
| 8 init 不执行 | 无效果 | 名称不匹配直接 return | 核对名称，必要时加回调试日志 |
